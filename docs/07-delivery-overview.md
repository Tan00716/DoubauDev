## 一、项目目标

为融合 Thronefall（即时建造 + 守城节奏）、Wanderburg（城堡成长）、Legion TD、Roguelite 卡牌构筑、天赋与 Meta 成长的独立游戏，产出一套可直接进入开发的完整《Game Design Master Plan》。覆盖原始需求全部 39 个章节，以系统联动优先、拒绝简单拼接参考游戏系统、最终设计必须答到开发可直接开工的程度。

## 四、一致性检查

1. **设计与技术一致**：核心设计文档中的硬约束（同屏 230 实体、2.5D 正交、数据驱动架构、PC/Steam）在技术架构文档中逐条继承并落实为 Unity URP + GPU Instancing + 流场 + ScriptableObject 方案。技术架构未发现与核心设计不可调和的冲突。
2. **Steam 文案与设计一致**：商店页所有卖点（白天建造 / 夜间战斗 / 双层牌库 / 指挥官 / 零数值 Meta）均可指回设计主文档对应章节，无虚构功能或夸大承诺。
3. **审计修复闭环**：2 条阻断级问题 + 9 条重要级问题已全部在设计主文档中修复并留有修订记录；建议级 12 条已列入后续迭代计划，不影响开工。
4. **跨文档术语一致**：Army Scale / Build / Roguelite / Meta 等核心术语在四份文档中定义统一。

## 七、风险与建议

- **最大风险**：战斗数值未经模拟器验证即进入全面开发，可能导致中期大规模返工。建议在 MVP 阶段用 2–3 周时间跑通核心战斗循环的数值闭环，再扩展至完整 8 昼夜。
- **技术风险**：同屏 150 敌人的流场 + GPU Instancing 方案虽理论上可行，但未在目标硬件上实测。建议在原型第一周就做敌群压力测试，若性能不达标，需回调军团规模或引入 LOD/合并网格降级。
- **AI 开发风险**：大量 AI Coding 协作可加速开发，但代码一致性、Game Design Drift、资产风格漂移是真实风险。技术架构已给出缓解方案（强制代码审查、统一资产风格指南、人工验收关卡），需在项目初期就建立流程纪律。
- **下一步动作**：以 MVP 为目标启动原型开发；MVP 必须能真实验证核心 Hook（白天建堡、夜里守城、双层牌库）。
